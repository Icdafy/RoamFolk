# 工程与资源规范

## 阶段边界

v0.1.0 已是不可覆盖的文档发布。本批以 v0.1.1 完成第一阶段「工程准备」，下一阶段为 v0.2.0「大厦入口」。本次样片是原创三层建筑体块，仅用于验证资源管线，不是正式 25 层大厦、21 层样板或系统原型。

## 工程组织

- `app/`：React 页面、样式和加载/错误状态。
- `src/game/`：Three.js 运行模块和楼层注册；通过动态导入保持 WebGL 仅在客户端初始化。
- `shared/types.ts`：FloorDefinition、AvatarDefinition、InteractableDefinition、SaveGame、WorldSession。
- `components/ui/`、`hooks/use-mobile.ts`：Sites 自带 Shadcn 组件，保留原样；lint 忽略供应商代码，TypeScript 仍检查整个工程。
- `assets/source/`：可编辑 Blender 源文件，使用 Git LFS。
- `assets/references/`：参考资料及来源说明。尚未收到楼层参考图片。
- `public/assets/`：网页可直接加载的真实二进制模型和资源清单，禁止 LFS 指针。
- `tools/`：建模脚本、环境检查、资源检查和发布打包。
- `tests/`：楼层进入边界和资产契约测试。
- `server/`：保留联机阶段入口；目前没有游戏服务器。
- `.work/`：忽略的下载、临时脚手架、检查日志和发布包。
- `tools/blender/`：忽略的本地 Blender 便携程序。

网页保留 `@openai/create-sites@0.3.0` 的 Vinext / Vite / Cloudflare Worker 构建约定。Worker 只负责网页交付，不是多人游戏服务器；没有 D1、R2、API 密钥或用户数据服务。脚手架依赖发现安全公告后，按 peer dependency 约束统一升级并锁定，详见 package-lock.json。

## Blender 环境

使用 [Blender 4.5 LTS 官方维护版本](https://www.blender.org/releases/4-5/) 的 4.5.13 Windows x64 便携版。本地位置：

`tools/blender/blender-4.5.13-windows-x64/blender.exe`

官方来源：[下载目录](https://download.blender.org/release/Blender4.5/)。
安装包 SHA256：`b5fdf800ce65fa2f209e8f68d02667e4d720fa1c42f247c72d1882ab04decba6`，已与官方同版本 sha256 文件比对。

新机器可下载该便携版解压到上述目录，或设置 `BLENDER_PATH` 指向已有 Blender。程序和安装包不提交 Git。验证环境运行 `npm run doctor`；重新生成样片运行 `npm run assets:generate`，该命令会重写同名样片源文件和 GLB，手工修改样片前请另存副本。

## 资源约定

- 1 Blender 单位 = 1 米；Blender Z 向上，glTF 自动转换为 Y 向上；网页导航平面为 X/Z。
- 物体前缀：ENV_ 环境、ANCHOR_ 锚点、MAT_ 材质。正式资源追加楼层或角色标识。
- Blender 自定义属性 `roamfolk_id` 是稳定标识，`roamfolk_kind` 指定用途；导出 `export_extras=True`，在 Three.js 的 userData 中读取。
- 样片锚点必须有 `roamfolk_fixture=true`，不得注册为正式交互物。锚点坐标由 Blender glTF 导出器转换，不能只复制 Z-up 坐标。
- 新正式楼层置为 open 前必须同时提供模型、预览图、正交镜头、出生点、导航数据和交互物；联合类型不允许只有编号就标为 open。
- 单层模型、纹理等压缩资源总预算为 20 MB；当前检查器只检查单 GLB 样片大小、10 万三角面预算、内嵌资源及必需锚点。正式多文件资源加入后需扩充为整层预算，不能拿样片检查代替正式楼层验收。
- 当前材质无外部纹理，GLB 包含所有需要的网格和材质。
- 样片预览按需渲染，限制像素比为 1.5，使用固定正交镜头；销毁时中止加载、移除监听器并释放几何体、材质、纹理、阴影和 WebGL 资源。
- 页面无持续动画，系统「减少动态效果」同时禁用界面过渡。

## 接口状态

共享类型已经定义，但不是实现承诺。WorldSession、IndexedDB 存档、版本迁移、A*、碰撞、角色和活动尚未实现，留待后续阶段。八个角色方案仍在完整计划中，不为尚无模型的角色创建虚假可用定义。

## 发布流程

1. `npm ci` → `npm run doctor` → `npm run check` → `npm run build`，核对页面和模型 HTTP 响应。
2. 更新版本、README、CHANGELOG 和本次验收记录；不覆盖已有标签。
3. 提交源代码，GitHub 推送成功后核对 SHA；使用 Sites 临时凭据按命令推送同一提交，凭据不得写入文件或 Git 配置。
4. 干净工作树执行 `npm run release:package`，输出构建 ZIP、SHA256、包内清单和启动说明。
5. 用 Sites 官方打包脚本打包同一构建，保存版本，部署到所有者私有访问；等部署终态成功再交付 URL。
6. 创建对应 Git 标签和 GitHub Release，上传构建包和校验文件。核对 main、标签、Release 和 Sites 记录的源提交。
7. 任一步失败保留本地成果，在发布说明标记待同步；不得宣布全部同步成功。

GitHub Actions 在 main 推送和 PR 上执行类型、lint、测试、资源检查与构建。WebGL 观感、缩放按钮、失败恢复及设备帧率仍需实机验收；自动检查不能替代它们。
